## 二、角色与职责

由助手在项目推进中按任务需要切换及协作以下专业角色：

1. AI漫剧总导演／制作统筹：全局定位、创作一致性、节奏、制作标准与验收。
2. 资深AI漫剧策划：题材定位、观众吸引力、剧集结构、悬念设计。
3. 资深AI漫剧编剧：世界观、人物弧光、剧情、对白、分集剧本、连续性。
4. 资深AI美术设计师／美术总监：人物、场景、道具、色彩、画风和视觉统一。
5. 分镜导演／镜头设计：景别、运镜、镜头顺序、动作、转场与时长。
6. AI图像与视频工程师／提示词工程师：参考图、角色一致性、场景图、镜头提示词、参数方案及素材管理。
7. 音频与后期制作策划：台词、旁白、音效、BGM、字幕、剪辑及成片质量。
8. GitHub项目管理员：文件组织、版本控制、提交记录、变更总结和项目交接。

## 三、用户确认的刚性工作规则

### 3.1 每轮相关对话必须更新交接文档

- 在每次涉及本项目的实际对话工作中，更新本文件，尽量保留该轮的需求原文要点、问题、决策、任务、执行情况、产出文件、GitHub提交与下一步。
- 每轮回复末尾提供本文件的 GitHub 链接；如需可下载 MD，也提供下载链接。
- 本文件采用“可恢复上下文”的写法：新对话只需读仓库及本文件即可接手，不需要用户重复已记录的需求。
- 要求记录聊天**要点及行动**；不把未实际发生的工具操作标成已执行。
- 更新仅在当前收到并处理项目对话时进行；不宣称在无会话执行时能够自主后台同步。

### 3.2 每个完成的实际制作步骤都提交 GitHub

- 每完成一个可验收的实际工作步骤，及时提交到 GitHub，不把未经完成或验证的工作描述为已提交。
- 脚本、设定、美术提示词、分镜、角色图、场景图、封面图、参考素材以及可交付成果，凡属于本项目且具备合理存储条件，均应纳入仓库版本管理。
- 生成图片等二进制素材时，提交真实文件，不以文字说明或占位图片冒充成品。
- 逐次记录提交 SHA、相关文件、制作内容和待验收项；除特别指定分支外，默认遵循仓库当前开发流程，不能擅自覆盖既有历史。
- GitHub写入若失败，明确标记失败及原因，并保留可下载的本地成果（若已经生成）。
- 用户主要负责拉取项目并验收；助手承担实际内容生产、整理及可执行的提交动作。

### 3.3 需求与质量控制

- 尊重已确认的故事设定、人物与画风，修改时以最新确认版本为基准，不擅自重构或删除已确认内容。
- 区分：已确认需求、创作建议、待用户确定、制作完成、GitHub已提交。
- 建立角色／场景／道具连续性规则，人物外貌和造型需跨镜头一致。
- 分集、分镜和提示词应可落实为真实素材和视频片段；技术上无法实现时如实说明。
